#+TITLE: Emacs research and development environment

Personal configuration for Python/R analysis, Quarto manuscripts and
Zotero–Obsidian literature work. It extends ordinary Emacs with the existing
ESS, lsp-mode, Citar and completion stack. The current implementation plan
and acceptance gates are in [[file:doc/development-roadmap.org][the development roadmap]].

* Supported environment

Validated locally with the separately installed Linux Emacs 31.1 PGTK/Wayland
build, xwidgets, native compilation and tree-sitter. The Snap installation
remains independent. See [[file:doc/linux-xwidgets.org][build and desktop notes]]. Do not replace the
selected executable or rebuild Emacs to adopt these configuration changes.
Other platforms and long-running sessions need separate acceptance checks.

* Installation, updates and recovery

This checkout uses Straight and existing builds under =straight/=. Preserve
that directory and =var/= when backing up or moving the current installation.
Review the Git diff before adopting a change, save buffers, then restart
Emacs. Configuration edits do not update the running session automatically.

The committed =straight/versions/default.el= pins 134 source repositories,
including recipe providers. The checked bootstrap installs the recorded
Straight revision and preserves failed or locally changed checkouts.
Source restoration, native package rollback and disposable configuration
startup are tested; a complete Internet-only install and native helper
rebuilds on another machine remain unverified. See [[file:doc/package-recovery.org][package restore/update/rollback]]
before changing an existing installation. =M-x awc-packages-audit= checks its
sources; =awc-packages-write-snapshot= writes a new review candidate without
updating or pushing packages. Do not blindly update all packages.

New file buffers use central backups and auto-saves. Use =M-x recover-this-file=
in a visited file or =M-x recover-session= for ordinary file recovery after a
crash. Vault notes retain their existing recovery directories; visit the note
before using =recover-this-file=. Review recovered text before saving. See
[[file:doc/reliability-and-recovery.org][recovery, execution policy and rollback]] for exact behavior and limitations.
Recovery data and personal Zotero associations are ignored by Git and require
separate machine backups.

Customize choices now persist in =var/preferences/custom.el=, outside Git,
with private directory/file permissions. They load after module defaults;
execution confirmation and recovery defaults remain active. See
[[file:doc/preferences-and-bindings.org][preferences, explicit trust and binding changes]] for failure recovery and rollback.

P0c2 checks normal startup, missing optional tools and a bounded two-project
session. It fixes immediate R document cancellation, Python REPL helper
cleanup and missing-Quarto inspection buffers. See
[[file:doc/startup-and-session-reliability.org][startup/session QA, resource ownership and limits]].

* External dependencies

- General tools: Git, ripgrep and the configured shell; Aspell for spelling.
- Quarto: the tested 1.4.530 installation, Node.js and its =yaml= module.
- Python: a deliberately created project environment; Pyright for assistance;
  Jupyter/kernel and analysis dependencies only when that workflow needs them.
- R: ESS plus project-installed packages; =languageserver= for assistance,
  =httpgd= for plots, =knitr/evaluate/jsonlite= for execution, and
  =reticulate/rmarkdown= for mixed documents and rendering.
- PDF/LaTeX: PDF Tools' installed helper and the project's TeX toolchain.
- References: an existing vault and bibliographies; running Zotero with its
  local API enabled only for explicit imports. Obsidian is optional for editing
  the same Markdown files. Credentials never belong in this repository.

* Testing

Run the small suite without third-party Emacs packages or external analysis
software (also used by [[file:.github/workflows/safety.yml][CI]]):

#+begin_src sh
emacs-xwidgets -Q --batch -l test/run-safety-tests.el
#+end_src

With the existing Straight packages and Quarto tools:

#+begin_src sh
python3 test/run-quarto-checks.py --suite core --keep
#+end_src

Normal terminal startup measurements and real two-project lifecycle checks
(requires existing R/Python/Quarto tools and permitted loopback servers):

#+begin_src sh
python3 test/run-reliability-checks.py --suite all --keep
#+end_src

For disposable Jupyter/renv installation and a separate 15-minute Wayland
session, see [[file:doc/external-and-graphical-validation.org][external and graphical validation]]. The graphical runner uses
the retained integration fixture, private configuration state and its own socket.

Explicit pinned-source restoration/build/rollback check, using installed
sources read-only and fresh disposable checkouts:

#+begin_src sh
emacs-xwidgets -Q --batch -l test/package-restore-check.el
#+end_src

=--suite all= additionally needs R =renv/languageserver=, the Python runtime
packages and TeX described in [[file:doc/quarto-source-editor.org][the integration guide]]. Missing dependencies
fail explicitly; installation requires =--install-dependencies= and is confined
to disposable fixtures. Tests do not use personal libraries, notes or datasets.
